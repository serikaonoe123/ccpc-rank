# CCPC Rank · 历史榜单实验室

静态、浏览器本地运行的 CCPC 动态榜单工具。新规则依据 2026 CCPC Online Contest N 题题面：单题通过数达到 50 或全体队伍的 20%，或比赛进入第 240 分钟，公开该题。该题面注明规则当时尚未最终定稿。

## 运行

无需安装依赖，Node.js 18+：

```powershell
git clone https://github.com/serikaonoe123/ccpc-rank.git
cd ccpc-rank
npm run dev
```

访问 http://127.0.0.1:4173 。测试：`npm test`。

`dist/` 内为完整静态站点，可部署到 GitHub Pages 或其他静态托管服务。`server.mjs` 只用于本地预览；`.openai/hosting.json` 为现有 Sites 站点的部署配置，本地运行和其他静态托管服务不需要此文件。

## 功能

- JSON 与提交 CSV 导入，逐条回放，时间线和倍速。
- 直接导入 SRK v0.3.13 ICPC 榜单（`.srk.json`），读取 `rows/user/statuses/solutions`，支持多语言名称、各类时间单位及原始罚时设置。
- 最终榜单 CSV、TSV、标准 HTML 导入为快照，不推测缺失的历史。
- 50 队 / 20% / 240 分钟 OR 判断，可配置。
- 公开前整列统一隐藏，不显示单元格状态和题目统计；队伍总分持续更新。
- 第 240 分钟起题目全公开，240 分钟（含）后提交进入常规封榜；最终榜单按钮揭开赛末前全部成绩。
- 队伍榜、学校榜、搜索、打星队伍、并列排名、当前视图 CSV 导出、原始 JSON 备份。
- 金、银、铜牌展示及导出，可配置各档比例，动态榜显示当前预估、最终榜显示模拟结果。
- VP 训练：真实计时、暂停继续、刷新恢复、外部 OJ 判定手动记录、撤销记录、虚拟排名和复盘导出。
- 文件在浏览器解析，不上传；历史赛事存储于 localStorage，存在浏览器配额限制。

## 数据格式

```json
{
  "title": "历史比赛",
  "duration": 300,
  "problems": ["A", "B"],
  "teams": [{"id": "1", "name": "队伍", "school": "学校", "unofficial": false}],
  "submissions": [
    {"teamId": "1", "problemId": "A", "time": 10, "verdict": "WA"},
    {"teamId": "1", "problemId": "A", "time": 25, "verdict": "AC"}
  ]
}
```

time 单位为开赛后的分钟，可使用小数；计分时首次 AC 分钟向下取整。时间达到 duration 的提交不计分。CE 不计罚时。包含 submissions 字段表示提交级数据（包括空数组）；没有此字段表示最终快照，队伍通过 `results: {"A": {"solved": true, "time": 25, "wrong": 1}}` 提供各题记录。

CSV 最终榜表头示例：`name,school,A,B`，单元格例：`+1 00:25`、`+ 25`、`-2`、空白。UTF-8 CSV 可由 Excel 另存；不直接支持 xlsx。提交 CSV 表头：`teamId,name,school,problemId,time,verdict`。

HTML 支持静态表格，表头含 Who / Team / Name / 队名 / 队伍 和单字母题目列。复杂合并表头、图片、动态网页壳需要转为标准格式。

本工具是本地分析工具，隐藏只影响显示，浏览器中仍持有原始文件。若用于正式公共比赛，应增加后端访问控制并由服务器过滤隐藏数据。演示赛全部为模拟数据，非真实历史成绩。

默认打星队伍计入揭榜阈值分母与通过数，但不占正式队伍排名；学校榜只取正式队伍最高成绩。所有队伍均不因零提交而过滤。不存在多端同步和多人协作功能。

规则来源：https://codeforces.com/gym/106725/problem/N

## SRK 标准榜单

在「导入历史榜单」中直接选择 `.srk.json`，无需把 `rows` 改为 `teams`。导入弹窗可下载不含真实参赛数据的 SRK 示例模板。

- 有完整、可核对的 `statuses[].solutions` 时读取逐次提交，支持回放与 VP。`FB` 按通过处理，`RTE` 转为运行错误，`NOUT`、`CE` 等是否计罚遵循原始 `noPenaltyResults`。
- 只有汇总状态或记录不完整时，以最终/封榜快照导入，保留已知结果及待揭榜状态，不推测缺失的提交时间，不启用 VP。
- 自动采用原始 `sorter.config.penalty`、时间精度与取整配置，以及由比赛时长和 `frozenDuration` 得出的封榜起点。CCPC 的动态公开阈值仍由当前规则设置决定。
- 支持前三档为 `gold/silver/bronze` 的无额外过滤 ICPC `count` 固定奖牌名额；`noTied: true` 时严格按名额分配，同分保持原榜行序。比例、混合或其他自定义分段保留在元数据中，并明确提示使用自定义比例模拟。
- 可在「赛制规则」中保存自定义设置，或恢复采用原榜计分与奖牌名额。学校榜使用自定义比例，不套用队伍固定名额。VP 固定保存开赛时的完整规则与名额。
- 不支持将 OI / `score` 排序榜单当作 ICPC 导入。

格式参考：[SRK 官方说明](https://srk.algoux.org/en/guide/rows)。

## 奖牌设置

在「赛制规则」中设置金、银、铜牌比例，默认分别为 10%、20%、30%。比例为各档独立占比，名次线使用累计比例向上取整：100 支正式队伍对应第 10、30、60 名。边界同分队伍获得同档奖牌，因此实际数量可能扩展。零解题队伍无奖牌，打星队伍与 VP 不占名额。学校榜在正式学校去重后独立计算。搜索和翻页不改变奖牌结果。此设置只用于模拟，不代表原赛事官方奖项。

## VP 训练

1. 在「VP 训练」页、历史赛事卡片或动态榜单点击「开始 VP」。只有包含完整提交记录的赛事支持 VP。
2. 填写队名和学校后开始真实计时。请自行在外部 OJ 阅读题面、提交代码，再在 VP 控制台记录 AC / WA / TLE 等判定；本工具不提供题面和代码自动评测。
3. 每条记录使用当时的 VP 用时。首次 AC 计分、之前的计罚错误按开赛时规则计算；可撤销最后一条误录判定。
4. 计时使用已累计用时加当前运行区间的真实经过时间，刷新、离开页面或关闭浏览器期间继续计时；主动暂停才停止累计。进度与记录存于当前浏览器。
5. VP 进行中禁用快进、传统榜、最终榜和该赛事原始数据备份。自己的成绩始终可见，其他队伍遵守动态揭榜与常规封榜。VP 不改变历史队伍排名、奖牌名额、题目通过数和揭榜阈值。
6. 到时自动结束，也可提前结束；结束后用自己的已记录成绩与完整历史最终榜比较，并显示模拟奖牌。退出 VP 视图后可自由回放。可从「VP 训练」页返回过去的训练记录或导出 VP JSON。

VP 会固定使用开赛时的计分与奖牌配置。该功能用于本地自助训练，浏览器仍持有原始历史数据，界面隐藏不等于防作弊隔离。清除浏览器站点数据会同时清除保存的 VP 进度；导出的 VP JSON 为备份，当前版本不支持重新导入该训练进度。
